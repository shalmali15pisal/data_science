How to use this walk it top to bottom, every case

Four questions, in order: is there interference at all → what's causing it and can it move → does it resolve fast or need time to mature → which design follows. Every one of the 12 cases traces a specific path through this same chart.

Reading a case through this chart — Order Batching example

Shared resource? YES (dasher supply) → not zero-sum/systemic, it's physical/economic → can it move? NO, orders are anchored → zone/cluster unit is fine → is it temporal? FAST (resolves within a delivery, no adaptation needed) → SWITCHBACK.

Peak Pay example — same chart, different path

Shared resource? YES (dasher supply) → physical/economic → can it move? YES, dashers can drive to another zone → unit must be the WHOLE MARKET → is it temporal? FAST (resolves within one shift) → still lands on repeated-window replicates, but at market level → a hybrid, closer to DiD run across repeated windows.

How to use this self-test

Only the prompt is shown. Talk through: interference reasoning → unit of randomization → primary/secondary/guardrail metrics → statistical test → sample size approach → duration. Then reveal and check yourself.

⚡ The one thing that never changes read this first

Every case in this console uses the IDENTICAL two-sided hypothesis test. H0: no difference. H1: a difference exists. Alpha=0.05, power=80%, z_alpha/2=1.96, z_beta=0.84. This machinery never varies.

n = 15.68 × sigma² / MDE² <- SAME formula, every single case

The only thing that ever changes is what sigma means and how much work it takes to compute correctly:

  • Sigma measured at the exact same level you're randomizing on (user tests, merchant clusters with enough historical weeks) → plug straight in, done
  • Sigma measured at a FINER level than your unit of randomization (Case 1: order-level sigma, but you randomize blocks) → need [F3]/[F4] DEFF to correctly translate up
  • Sigma for a RATIO, not a plain average (acceptance rate) → need [F5] delta method to even get a valid variance, before DEFF applies on top

DEFF, delta method, and weeks-per-cluster averaging are never a DIFFERENT statistical framework — they're all just different amounts of work needed to get one correct number (sigma) into the one unchanging formula above.

[F1] Sample size — continuous metric, no clustering

n per arm = (z_a/2 + z_b)^2 * 2*sigma^2 / MDE^2 ≈ 15.68 * sigma^2 / MDE^2 (80% power, 5% alpha, 2-sided)

Use for standard user-level A/B tests with a continuous outcome (delivery time, revenue).

[F2] Sample size — proportion/ratio metric, no clustering

n per arm = (z_a/2 + z_b)^2 * [p1(1-p1) + p2(1-p2)] / (p1-p2)^2

Use for conversion rates, acceptance rates — but ONLY when there's no clustering. Never use this alone in a switchback design.

[F3] Design Effect (DEFF)

DEFF = 1 + (m - 1) * ICC

m = avg units per block. ICC pulled from historical order-level ANOVA decomposition — never assumed. Behavioral/decision metrics (acceptance rate, retention) tend to have HIGHER ICC than physical metrics (delivery time), because individual "pickiness" is a stable trait, not independent noise.

[F4] Inflated sample size + blocks needed

n_inflated = n_per_arm * DEFF blocks_per_arm = n_inflated / m total_blocks = blocks_per_arm * 2

[F5] Delta-method variance — RATIO metrics in a clustered design

L_i = Y_i - R_hat * N_i (linearized pseudo-value per block) Var(R) ≈ Var(L) / (k * N_bar^2) feed into [F1] in place of sigma^2

Needed because a ratio's variance isn't a simple proportion formula once numerator AND denominator are both random and correlated (e.g. same dasher makes multiple correlated decisions in one block).

[F6] Test duration — switchback

duration = blocks_per_arm / (blocks_available_per_arm_per_calendar_unit)

[F7] DiD / matched-market sample size

Treat market×period as the unit, apply [F3]/[F4] the same way — but feasibility (how many eligible markets exist) usually binds before a clean MDE-driven number does.

[F8] Synthetic Control — no traditional power formula

Validity depends on donor pool size (5+ candidates) and pre-period fit quality (RMSE). Use placebo tests for validity, not a sample-size calc.

ICC calculation (ANOVA method)

ICC = (MSB - MSW) / (MSB + (n0-1)*MSW) MSB = SSB/(k-1) MSW = SSW/(N-k) n0 = (N - Σn_i²/N)/(k-1)

Requires ORDER-LEVEL (not pre-aggregated) historical data at the same block granularity you plan to test with.

Canonical procedure apply to any case

1

Define the block — the unit of randomization (e.g., zone × 2hr, zone × day, market × week). Must fully contain the interfering resource's reach (see each case's "Why Switchback" reasoning).

2

Get baseline stats from HISTORICAL data — mean, standard deviation (continuous) or baseline rate (ratio) for the metric, pulled from before the test, at the same block granularity you plan to use.

3

Choose your MDE — smallest effect that would actually change the business decision. Not "as small as possible" — going from detecting 1.5→0.4 units of effect requires ~16x the sample (inverse SQUARE relationship).

4

Compute naive sample size — [F1] for continuous, [F2] for ratio, using alpha=0.05, power=80% as defaults unless told otherwise.

5

Get m and ICC from historical order-level data — m = avg units per block; ICC via the ANOVA formula, computed at the SAME block granularity chosen in step 1. Never assume ICC — state you'd pull it from a variance decomposition.

6

Inflate: DEFF = 1+(m-1)×ICC, then n_inflated = n_naive × DEFF → blocks_per_arm = n_inflated/m → total_blocks = blocks_per_arm × 2.

7

For RATIO metrics specifically — insert delta-method linearization [F5] BEFORE step 6's DEFF inflation. Two separate corrections stack: delta method fixes the variance formula itself; DEFF then corrects for block clustering on top of that.

8

Compute duration [F6] — total_blocks ÷ (blocks available per calendar unit, e.g., zones × dayparts/day, or zones × days/weekend). If duration is too long, the fix is usually EXPANDING geographic footprint (more zones running in parallel), not shrinking block granularity — shrinking granularity risks violating the reach constraint from step 1.

9

Consider CUPED if a correlated pre-period covariate exists — can shrink required duration without changing anything about the design (see SRM & CUPED tab).

Dataset schema — RATIO metric real data, delta method example

One row per block, but TWO raw columns (numerator, denominator) before any ratio is computed. This is the ACTUAL 40-block data used to verify the delta-method linearization earlier (pooled R_hat = 0.5979).

block | n_offered | n_accepted | L_i = n_accepted - R_hat*n_offered 1 | 38 | 21 | -1.721 2 | 44 | 29 | 2.691 3 | 43 | 27 | 1.289 4 | 50 | 36 | 6.103 5 | 37 | 25 | 2.877 6 | 41 | 30 | 5.485 7 | 50 | 32 | 2.103 8 | 42 | 24 | -1.113 9 | 35 | 16 | -4.928 10 | 49 | 29 | -0.299 ... (40 blocks total)

L_i is computed AFTER you have R_hat (the pooled ratio across ALL blocks: sum(n_accepted)/sum(n_offered)) — this linearized column is what actually gets fed into the WLS regression as the outcome, weighted by n_offered. Never regress the raw ratio (n_accepted/n_offered) directly — that's the exact mistake that understates variance by 2.7-3.9x at realistic ICC.

Sample Ratio Mismatch (SRM) diagnostic

Checks whether the observed treatment/control split matches the expected randomization ratio — a chi-square goodness-of-fit test.

chi-square = Σ [(observed_i - expected_i)^2 / expected_i] (1 df, 2 arms)

The critical trap: run SRM on BLOCK COUNTS, never order counts — block sizes vary naturally (dinner vs. lull), so an order-count check will falsely flag "significant mismatch" even under perfectly correct randomization.

  • Run it overall AND per stratum (zone × daypart) — a global check can mask a stratum-specific bug
  • Use a strict threshold, p < 0.001, not 0.05 — you want strong evidence before crying "bug," not a hair-trigger on noise

CUPED variance reduction

Uses a pre-experiment covariate correlated with the outcome (but unaffected by treatment) to shrink variance — increasing power for the SAME sample size.

Y_adjusted = Y - theta * (X - X_bar) theta = Cov(Y, X) / Var(X) Var(Y_adjusted) = Var(Y) * (1 - corr(X,Y)^2)

Verified worked example (100 blocks, pre-period X correlated with outcome Y at r=0.573):

Var(Y) without CUPED: 53.16 Var(Y_adj) with CUPED: 35.71 Variance reduction: 32.8%

Matches the theoretical prediction (1 − 0.573² ≈ 0.672) almost exactly. Both estimate the SAME true effect — CUPED just does it with less noise.

For switchback specifically: use each block's own HISTORICAL (pre-test) average for the same metric as X — e.g. a zone-daypart's historical avg delivery time from weeks before the test. Effectively "free" power — can shrink required duration without changing the design itself.

The core regression verified by hand

beta_hat = (X'WX)^-1 X'WY

X = design matrix (intercept + treatment 0/1 + zone/daypart dummies, one reference category dropped per variable to avoid perfect multicollinearity). W = diagonal matrix of weights (n_orders per block — WLS, not OLS, because Var(block mean) = sigma²/n_i). Manually solved and matched statsmodels output to 5 decimal places.

What the treatment coefficient actually IS

NOT a standalone "treatment group value" — it's already the treatment-minus-control delta, computed within each stratum. Verified by predicting Zone_B+lunch at treatment=0 vs 1: the difference exactly equals the coefficient. With a plain 0/1 dummy alone, beta1 = treatment_mean − control_mean, exactly.

Terminology: "treatment" in the data = an arm-membership INDICATOR present on every row (0 or 1), not "the treatment arm's value." The COEFFICIENT on that column is the effect.

Where control data enters

Same X matrix and Y vector as treatment — distinguished only by treatment=0 vs 1. Proven necessary: removing all control rows makes the treatment column constant (all 1s), collinear with the intercept → X'X becomes singular → Python throws an actual error. Control rows are what give the treatment column its variation.

Cluster-robust "sandwich" SE verified by hand

Var(beta_hat) = (X'WX)^-1 [Σ_g X_g'W_g u_g u_g' W_g X_g] (X'WX)^-1

g = clusters (day, weekend_id). Relaxes independence from "every block independent" to "independent only across clusters." Manually implemented and matched statsmodels to 5 decimals.

Full pipeline, input → output

1

Raw order-level logs (one row per order)

2

3

4

5

t = beta_hat / SE(cluster-robust) → p-value, 95% CI via t-distribution

6

7

Decision: primary first → guardrails independently → heterogeneity w/ honest power caveats

Pseudo-replication, precisely

Treating correlated within-block orders as independent makes the TRUE standard error understated by the naive calculation — not "4x larger than it actually is." True_SE = Naive_SE × √DEFF. Small (wrong) SE in the denominator of t = effect/SE → artificially large t-stat → false positive.

Ratio metrics: TWO separate corrections needed

  • DEFF/clustering corrects for: randomization unit is the block, not the individual event
  • Delta method corrects for: even at the correct block level, a ratio's variance isn't a simple proportion formula, since numerator & denominator are both random and correlated

At realistic ICC=0.10–0.15 for a behavioral metric, naive approach understates required sample size by 2.7×–3.9×.

Total vs. average — the audit-found principle

Average-per-order-within-block is only valid when order count is EXOGENOUS to treatment. When treatment's mechanism changes volume itself (pricing, promos, discounts), volume is a MEDIATOR — use TOTAL per block instead, weighted by HISTORICAL/pre-period volume, never in-period observed volume (a post-treatment, endogenous variable).

Preventing concurrent-experiment interference: Layers

Layer = a group of mutually-exclusive experiments testing the same/overlapping lever or touching the same decision/UI surface — regardless of stated "purpose."

bucket = hash(unit_id + salt) % 100

Same salt → same layer → mutually exclusive by construction. Different salt → different layer → statistically independent, safe to run simultaneously.

Governance: check an experiment registry before launch. If two experiments must share a population and can't be layered apart — run a factorial design (test the interaction term explicitly) or sequence them.

Rollout sequence, once a test wins

Design & registry checkconfirm no collision with running tests
Pilot / canary1-5% or a couple zones, days — bug/guardrail sanity check, NOT statistically powered
Full-power testper sample size calc, full duration
Decisionship / no-ship / iterate
Staged rollout5% → 25% → 50% → 100%, guardrails monitored EVERY stage, auto-rollback trigger
Long-term holdout2-5%, held back for months — catches novelty decay

Why not flip straight to 100%: the test population was a sample — operational strain that didn't show up at 15 zones might appear at true full scale (supply dynamics differ once EVERY dasher is affected simultaneously).

Why the long-term holdout: short windows can't distinguish a genuine effect from a novelty effect. Holding a group back for months checks if lift persists once the change becomes routine.
